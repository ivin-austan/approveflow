# jsPDF backend-worker spike

## Decision

jsPDF is retained for the Phase 2 foundation, subject to a production-readiness
gate before approved artifacts are implemented in Phase 7. The Node renderer and
AutoTable integration cover deterministic bytes from a fixed model, wrapping,
table splitting, and pagination.

## Confirmed constraints

- Built-in PDF fonts do not cover the required Unicode and RTL scripts.
- Production rendering therefore requires version-pinned Noto font assets,
  embedding, bidi processing, shaping fixtures, and license attribution.
- jsPDF's tagged-PDF support must be proven against PDF/UA-1 validators. It is
  not assumed merely because a PDF can be generated.
- Fixed creation timestamps, stable input ordering, pinned renderer/font
  versions, and controlled metadata are required for deterministic retries.
- Browser output is preview-only. Canonical approved artifacts are generated by
  the backend worker from immutable snapshots.

## Phase 7 acceptance gate

Before canonical rendering ships, add licensed Noto fixtures for Latin, Arabic,
and representative configured scripts; validate glyph shaping and bidi order;
exercise multiline comments, logos, repeated table headers, 500-page and 20 MiB
limits; compare retry hashes; and run an external PDF/UA validator. If jsPDF
cannot meet the approved accessibility or shaping requirements, present evidence
and obtain architecture approval before choosing another renderer.
